# 로그인 문제 쉬운 설명 (원인 추적 메모)

## 한 줄 요약
- 지금 문제는 "계정 전환 순간에 이전 계정 로컬 기지가 다시 로드될 수 있는 경로"가 남아 있는 것입니다.

## 지금 사용자에게 보이는 증상
- Google 로그인 후 로그아웃했는데,
- 다른 계정(또는 게스트)으로 들어가도
- 이전 Google 계정 기지가 계속 보입니다.

## 왜 이렇게 의심하는가 (코드 근거)

### 1) UID가 비어 있는 순간, 로컬 로드를 허용하고 있음
- `src/modes/city-sim/save.js:579`
- `src/modes/city-sim/save.js:582`
- `src/modes/city-sim/save.js:588`

설명:
- 계정 전환 직후에는 UID가 잠깐 비는 타이밍이 생길 수 있습니다.
- 그런데 현재 코드는 UID가 없을 때도 로컬 저장 데이터를 읽을 수 있게 되어 있습니다.
- 그래서 "방금 전 계정의 로컬 기지"가 다시 화면에 뜰 수 있습니다.

### 2) 로그아웃이 저장 실패 때문에 취소될 수 있음
- `src/modes/city-sim/auth.js:1233`
- `src/modes/city-sim/auth.js:1235`

설명:
- 로그아웃 전에 저장을 먼저 시도하는데,
- 저장 실패 시 로그아웃 자체를 중단합니다.
- 사용자는 로그아웃했다고 느끼지만 실제 세션은 유지될 수 있고, 이후 흐름이 꼬일 수 있습니다.

### 3) 로그인 완료 후처리가 여러 경로에서 동시에 동작할 수 있음
- `src/modes/city-sim/auth.js:1362`
- `src/modes/city-sim/auth.js:1372`

설명:
- redirect 결과 처리와 onAuth 콜백이 각각 동기화를 수행합니다.
- 타이밍이 겹치면 상태 반영 순서가 꼬여, 잠깐 이전 상태가 보이거나 덮어쓰기가 일어날 수 있습니다.

## 그래서 무엇을 먼저 고칠 것인가 (우선순위)

1. UID 미확정 상태에서는 계정 미검증 로컬 데이터를 로드하지 않게 수정
2. 저장 실패와 로그아웃을 분리해서, 필요 시 강제 로그아웃 가능하게 수정
3. 로그인 성공 후처리를 하나의 함수로 통합하고 경합 토큰 추가

## 이번 문제를 "확정"하기 위한 체크

1. Google A 로그인 후 로그아웃 -> 게스트 로그인 시 A 기지가 뜨는지 확인
2. 같은 테스트를 네트워크 느린 환경에서도 반복
3. 재현 시점에 아래 값을 기록
- 현재 UID
- local owner UID (`reclaim_citysim_v1__owner_uid`)
- 실제 로드 출처(원격/캐시/로컬)

이 3개가 모이면 원인이 맞는지 확정할 수 있습니다.
