# 사거리 리밸런스 계획서 (2026-02-21)

## 1) 목적
- 전투가 너무 근접에서 시작되는 문제를 해결한다.
- 유닛별 무기 특성(보병/기갑/항공/포병)에 맞는 교전 거리로 전장을 넓게 사용하게 만든다.
- 기준은 `사거리(range)`를 중심으로 잡고, 이동/배치 로직은 사거리 변경을 따라가도록 보정한다.

## 2) 현재 상태 요약
- 맵 기준 폭: `6000` (`data.js`)
- 실제 교전 사거리는 `getEffectiveRange()`에서 보정 적용 (`classes.js:240`)
- 현재는 글로벌 배율 중심이라, 일부 유닛은 여전히 체감 교전 거리가 짧다.
- 특히 `engineer` 미사일 사거리(`missileRange`)는 별도 값이라 통합 보정이 필요하다.

## 3) 리밸런스 기준 (핵심)
### 공통 기준
- 근접전(CQB): 220~380
- 중거리 교전: 450~900
- 장거리 교전: 1000~1600
- 초장거리(포병/특수항공): 1700~2400

### 1차 목표 유효 사거리(Effective Range)
- `infantry`: `280`
- `engineer`(소총 모드): `320`
- `drone_operator`(소총 모드): `320`
- `special_ops`: `420`
- `sniper`: `1400`
- `humvee`: `650`
- `apc`: `520`
- `mbt`: `1100`
- `aa_tank`: `1050`
- `apache`: `900`
- `blackhawk`: `650`
- `fighter`: `1800`
- `spg`: `2200`

### 미사일/특수 사거리 별도 기준
- `engineer/rpg missileRange`: `1300`
- `fighter missile engageRange`: 기존보다 +25~35%
- `spg`는 고각/재장전 특성 유지, 사거리만 상향

## 4) 구현 전략
## Phase A: 중앙 사거리 프로파일 도입
- `classes.js`에 유닛별 사거리 프로파일 테이블 추가
- `getEffectiveRange()`는 기존 배율 방식 대신:
1. 기본 사거리 계산
2. 유닛별 최소 목표값(`targetMin`) 적용
3. 맵 폭 비례 미세 조정(향후 확장)

## Phase B: 미사일 사거리 통합
- `engineer/rpg`의 `missileRange`도 동일한 프로파일 기준으로 별도 함수에서 계산
- 현재 `this.stats.missileRange` 직참조를 헬퍼 함수로 교체

## Phase C: 전투 거리 유지 로직 보정
- `_getCombatHoldDistance()`에서 지나치게 멀어지는 케이스를 상/하한으로 제어
- 사거리 증가 후에도 아군이 타겟 앞에서 겹치지 않도록 거리 슬롯 유지

## Phase D: 건물 사거리 동반 보정
- 거점/포탑/감시탑 사거리도 비율 상향 (권장 +25~40%)
- 유닛 사거리만 늘어나 건물 방어가 무력화되는 문제 방지

## 5) 검증 항목
1. 첫 교전 시작 거리: 기존 대비 명확히 증가
2. 기갑전에서 근접 난전 감소, 중장거리 교전 증가
3. 보병/기갑/항공의 역할 분리 유지
4. 포병이 과도하게 맵 전체를 즉시 압도하지 않는지 확인
5. 명령 모드(`move/stop`)에서 사거리 판정 정상 동작
6. FPS 저하/타겟팅 이상 없음

## 6) 적용 순서 (안전 롤아웃)
1. 사거리 테이블 + 보병/기갑 1차 상향
2. 항공/포병/미사일 상향
3. 건물 사거리 보정
4. QA 후 수치 미세 튜닝

## 7) 리스크 및 대응
- 리스크: 포병/항공이 지나치게 유리해짐
- 대응: `spg/fighter`는 사거리 상향과 함께 재장전/탄수/타겟 손실 조건 동시 점검

- 리스크: 유닛이 너무 멀리서 멈춰 전진전 느낌이 약해짐
- 대응: 유닛별 holdDistance 상한을 설정

- 리스크: 기존 밸런스 붕괴
- 대응: 사거리 프로파일만 되돌리면 즉시 롤백 가능한 구조로 구현
